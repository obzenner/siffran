# Empirica Docker spike support contract v1

This directory is the normative, adapter-independent support contract for Empirica 6's **current-only** generic Docker spike implementation. Its `/1` is the version of this internal support contract, not a runtime compatibility promise: runtime artifacts remain flat `/2`, runs remain `empirica.run/3`, public wire remains `empirica/v2`, and the observer remains `empirica-ui-view/v1`; no old runtime loader, migration, fallback, or translation exists.

`support-contract.json` is the closed machine-readable contract and `support-contract.schema.json` validates it. `make empirica-docker-support-contract-check` validates the data, checks its fixed policy/profile/probe mappings against the implementation, requires every refusal code to be a reason the code actually emits, verifies that every cited pinned fixture exists, and checks that the agent-visible public-contract clause `evidence/spike/limits` still equals its rendering from the code constants (`make empirica-spike-limits` rewrites it). The independent Docker fixture is owned by `scripts/generate_generic_docker_fixtures.py`; it contains literals from the G11 probe corpus and verbatim Docker CLI/Moby 20.10–29 forms and deliberately imports no production planner code.

## Normative boundaries

1. **Host support.** The daemon must be genuine Docker Engine/Desktop, serve native Linux `amd64` or `arm64` over one canonical local Unix endpoint, expose cgroup namespaces and default/builtin seccomp, and report `MemoryLimit`, `SwapLimit`, `CpuCfsQuota`, and `PidsLimit` true. Client/server patch versions, cgroup diagnostic strings, host-Python architecture, `NCPU`, `MemTotal`, and optional security options are diagnostics, not installed semantic authority. Current `NCPU` only seals the request's `min(2,NCPU)` CPU allocation; ordinary request/reobservation catches relevant drift.
2. **Image resolution.** One already-local image is resolved to the daemon image ID and canonical server-native platform. Pull, build, load, login, image inventory, context mutation, and daemon repair are outside scope; ambiguity, missing image, malformed identity/platform, declared volumes, missing qualification tools, or unusable uid 65534 fail closed.
3. **Sandbox policy.** The immutable numbers and fixed paths in `sandbox_policy` are framework authority. Authors control only image reference, argv, relative input declarations, and environment overrides within the flat `/2` draft.
4. **Lifecycle.** Production proves an exact owned bridge with no live endpoints before start and proves the container is configured to that bridge. Sole running membership is a qualification-only host-capability proof; a fast production exit is safe under the stated same-user threat model because prestart ownership/emptiness plus exact terminal container network configuration remain admitted. Natural exit 0 is PASS; another natural exit except 137 is FAIL; timeout, overflow, OOM, 137, forced/failed start, malformed observation, cleanup ambiguity, or authority drift is unavailable. Adoption and policy are separate gates: a candidate container is recorded after an ownership-only check (exact `Id`, compiled `Name`, every Empirica label); security static admission then runs on the same inspection, and its refusal is a clean unavailable followed by exact-ID removal. `Config.ExposedPorts` is image `EXPOSE` metadata and publishes nothing; `PortBindings`, `PublishAllPorts`, and every other host-surface field stay refused.
5. **Destructive authority.** Only a durably journaled 64-hex full ID authorizes removal. docker/cli `create.go` refuses a preexisting cidfile (`os.Stat`), creates it (`os.Create`) before `ContainerCreate`, writes the ID only after the daemon answers, and removes an unwritten file only on a non-killed exit; so an empty or missing cidfile is never absence. Without a written ID the exact-name candidate set decides: zero candidates proves absence, one is ownership-verified, recorded, and removed by full ID, more than one fails closed. Whatever the CLI exit, a create without a written ID retains its journal and the next recovery performs that lookup, because the daemon may still be finishing the create; a malformed cidfile is treated like a missing one. Exact absence requires a nonzero exit, stdout that is empty, `[]`, or `[]\n` (docker/cli flushes the empty JSON list as `[]\n`), and an anchored stderr message naming that same recorded ID. Names and labels are correlation only and never authorize deletion.
6. **Recovery.** Recovery is total and version-stable: it reads the closed operation data persisted in each journal (names, labels, staging token, recorded IDs), never re-plans the operation, and reuses the current effects. It proceeds only when the journal's recorded daemon identity (endpoint, server OS, architecture) equals the current one; capability facts are enforced for new execution, not recovery, so an engine upgrade or requalification never strands a journal. A journal from another endpoint or platform fails closed, because its IDs belong to another daemon.
7. **Qualification.** Five ordered probes share one absolute under-60-second deadline. Qualification writes only a private candidate; installation is a separate explicit revalidation and atomic publication. The networked probe must prove outbound HTTP or exit with the specific `network-egress-unavailable` reason and must observe sole membership before attach completion.
8. **Observer.** Public proof is historical and read-only. It exposes environment names, never values/fingerprints/lengths; independent stream counts/digests, never contents; and no host paths, endpoint, credentials, cidfile/journal, or destructive IDs. Authored environment values persist in private content-addressed run artifacts and must never contain secrets.
9. **Release status.** Every listed host/store cell remains `live-qualification-required`. Pinned fixtures and unit tests prove adapter semantics but are not live host evidence.

## Adapter traceability

| Obligation | Docker CLI input | Daemon observation / admitted equivalents | Emitted reason |
|---|---|---|---|
| Default namespaces | `--ipc private --cgroupns private`; omit `--pid`/`--uts` | PID empty/private; IPC empty/private; UTS empty only; cgroupns empty/private | `lifecycle-unavailable` |
| Cidfile authority | `--cidfile <absent reserved path>`, child umask 077 | absent before create; owner-only file with one full ID; otherwise the next recovery's one exact-name candidate verified by `Id`, `Name`, and every label | `cleanup-unavailable` |
| Private bridge | create bridge, bind create to exact full ID | exact ID/labels/bridge/non-internal; prestart `Containers` empty; terminal network ID exact | `lifecycle-unavailable` |
| Running membership | qualification attach plus concurrent bounded inspect | exactly the verdict full ID while running; production fast-exit uses the safe prestart fallback | `probe-failed` (qualification) |
| Resources | exact memory/swap/CPU/PID flags | four capability flags true and exact realized HostConfig values | `resource-limits-unavailable` (qualification) |
| Natural verdict | `container start --attach` | attach/terminal exact exit agreement; PASS 0, FAIL nonzero except 137 | `lifecycle-unavailable` |
| Exact cleanup | remove and inspect the journaled full ID | nonzero exit; stdout empty, `[]`, or `[]\n`; anchored `No such <resource>: <ID>` or `<resource> <ID> not found` | `cleanup-unavailable` |
| Observer privacy | no Docker operation | closed historical `/2` facts only | malformed proof omitted |

## Private stuck-operation diagnosis

A spike whose recovery or cleanup is unproved returns a public spike Fault with reason `cleanup-unavailable` only; nothing private is emitted or logged. Each unfinished operation is one owner-only directory `${EMPIRICA_SANDBOX_HOME:-~/.empirica-plugin/sandbox}/generic-runtime-v2/o-…` holding `journal.json` and, once Docker wrote it, `container.cid`. The next spike on the same Docker daemon (same endpoint, server OS, and architecture; capability or engine-version changes do not matter) recovers every such journal automatically before any new mutation, so first fix daemon or config availability and request a spike again.

When recovery stays stuck, list `generic-runtime-v2/o-*` and, for each directory, read `journal.json`:

1. **Daemon.** `authority` holds the `endpoint`, `server_os`, and `server_architecture` of the daemon that owns its IDs. If they differ from the current ones (for example after `docker context use rootless`), switch back to that endpoint and request a spike there, or act only through that endpoint.
2. **Recorded IDs.** `resource_ids.container` and `resource_ids.network` are the only destructive authority. A null container ID with a 64-hex `container.cid` is the cidfile-only case: that ID is the candidate.
3. **No ID.** With neither, find candidates read-only: `docker container ls --all --no-trunc --filter name=^/?<operation.container.name>$` (and `docker network ls --no-trunc --filter name=^<operation.network.name>$`). Zero candidates means nothing exists. Use exactly one candidate only after `docker container inspect <full-id>` shows the journal's `Name` and every label in `operation.container.labels`; more than one, or a mismatch, is not ours to remove.
4. **Removal.** Remove only exact full IDs (`docker container rm --force --volumes <full-id>`, then `docker network rm <full-id>`), prove each absent with `docker container inspect <full-id>` / `docker network inspect <full-id>` exiting nonzero with stdout empty, `[]`, or `[]\n` and stderr `No such …: <full-id>` or `… <full-id> not found`, then delete that one operation directory and its `staging/o-…` directory.

Never delete by name or label alone, clear the journal root wholesale, or invent an ID; unresolved ambiguity stays retained for recovery.
