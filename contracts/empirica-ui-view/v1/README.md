# empirica-ui-view/v1: the observer read model

What a human-facing view of the Empirica run store reads: every project, run and claim the
observer can read (`view.schema.json`), and one run's detail on demand (`run.schema.json`,
additive to its row). The plugin's observer (`plugins/empirica/application/observer.py`) is the
only producer, served on loopback by `plugins/empirica/adapters/observer/server.py` (ADR-0065).
A consumer joins, counts, filters and draws. It derives no state.

## Ownership

| Fact | Owner | How this contract holds it |
|---|---|---|
| Run status, claim kinds and states, audit and independence states, freshness states, artifact outcomes, reason codes and messages | `contracts/empirica/v2/public-contract.json` | `scripts/validate_ui_view.py` requires each schema enum to equal its registry list |
| Governance control mode and approval state | `contracts/empirica/v2/state.schema.json` | the same check |
| History step kinds | `plugins/empirica/application/history_records.py` (`HISTORY_KINDS`) | the same check |
| Claim state, blocker, audit state, residuals, freshness | the plugin's evaluation and projection (`core.evaluation`, `core.projection`) | `plugins/empirica/tests/test_observer.py` compares every run with the plugin's own `GetArgument` and `GetRun` |
| `evidence` and `review` | `plugins/empirica/core/observer.py` (`EVIDENCE_KINDS`, `REVIEW_STATES`: the only two classifications added here) | the enum check, and the scenario test in `test_observer.py` |
| Project name and repository | a repository given for it (`--repo`, matched by the plugin's identity, `adapters/state/identity.project_id`), else the one the bridge recorded for the project when it created a run (`adapters/state/locations.py`); the name is its folder name; the row's `label` is that name, else "Unnamed project", and `since` is its first run's time, so a consumer never numbers projects | `adapters/observer/source.py`, `FilesystemStoreTests` and `LocationsTests` in `test_observer.py` |

A run's detail also carries, from the ADR-0067 evidence model: per claim `records[]` (source, kind, quote, outcome,
`class`, `status`, `route`, `retrieve`, `spike_unavailable`, the human's `note`) and `decision` (`{outcome, answer,
route}`), and for the run `waiting[]` (the claims whose research or decision awaits a confirmation, by route). Every
message in it (residuals, claim blockers) is the registry's template with its typed parameters filled in once, by the
observer (`core.observer.reason_message`); a consumer never sees a `{name}`.

A `null` is unknown, never a default. A run the observer cannot fully read still appears with a
`diagnostic` that says why (the schema's `run.diagnostic` lists them). Only the facts it could
read are shown. `older-format` versus `unreadable` is decided with the plugin's own identifiers
and state validator: a different shape is age, and a current shape that breaks invariants is
damage.

## Fixtures

`fixtures/` is generated by `scripts/regen_ui_view_fixtures.py`, which builds real runs with the
plugin's v2 service (`plugins/empirica/tests/v2/observer_store.py`) and projects them with the
observer. `scenarios.json` maps each scenario name to its run key. A byte-identical copy ships in
`plugins/empirica/vendor/` for the UI's demo mode. `make contract-fixtures` regenerates both;
`make contract-check` fails when either is stale or invalid.
