# Empirica 6 single-container Docker spike MVP

Status: accepted architecture decision, direct replacement of the unreleased ADR-0071 multi-container candidate.

Decision source: accepted requirements artifact, SHA-256 `0c5c438e35794d74e6b94950a529e915fbbcb0a0c8aafb12af979eeaf4d1da0f`.

Development evidence: local probe bundle manifest SHA-256 `7ac2c9d9a37c2afa71967a9f65124c613bdb9b7748ee65a1bc066e4405acd575`. The machine-local probe bundle informed the decision; it is not shipped authority, qualification evidence, or a broad-support claim.

## Decision

Empirica 6 ships one single-container Docker spike. The author supplies exactly a local image reference, an exact nonempty argv vector, zero or more repository-relative file/directory declarations, and a bounded environment map under `empirica.spike-plan-draft/2`. There is no `/1` loader, schema, translation, compatibility path, or migration path.

The machine-readable normative Docker support boundary is [`contracts/empirica-docker-spike/v1`](../../../contracts/empirica-docker-spike/v1/README.md). This internal support-contract `/1` does not add a runtime compatibility surface.

The host resolves the already-local reference to the daemon's immutable image `Id`, raw and canonical OS/architecture, and refuses missing, ambiguous, volume-declaring, or server-nonnative images without pulling. Canonical architecture aliases are `aarch64 -> arm64` and `x86_64 -> amd64`; equality is against the Docker server's canonical platform, not the host Python process architecture. Creation uses the sealed ID with `--platform` and `--pull never`; `Config.Image` must equal that sealed ID, while the container's top-level image realization must be a well-formed digest. Admitted result facts bind `image_digest` to the sealed daemon image ID—not to a digest of mutable inspect metadata.

The host expands declared inputs once into a sorted captured-file union, excludes symlinks and `.git`, applies the 256-file/64-MiB aggregate/64-MiB per-file limits, stages one immutable tree, and mounts it read-only at `/inputs`. Empty input still yields the same empty `/inputs` mount. The author cannot control authority, profile, Docker options, host paths, mounts, resources, timeout, user, workdir, topology, services, aliases, or cleanup.

## Application checkpoint

The `/2` application seam has a bounded read-only local-image resolver port. Resolution returns the requested reference, immutable daemon image ID, raw image and server platform facts, declared-volume destinations, positive engine NCPU, and the exact qualified backend binding; the application canonicalizes the platform and refuses `image-not-local`, `image-reference-ambiguous`, `image-platform-mismatch`, `image-declares-volumes`, `malformed-required-result`, or `authority-drift` without starting a workload. The G11c Docker adapter implements this port with one bounded `docker image inspect --format` call, classifies missing and ambiguous local references without pulling, and projects only ID, platform, and declared-volume facts.

Workspace capture expands declarations through directory descriptors without following symlinks, skips nested symlinks, `.git`, and special files, rejects those forms when explicitly declared, sorts one destination-relative file union, applies count/per-file/aggregate ceilings from metadata before each bounded read, and then revalidates file identity and size after reading. Captured bytes stay only in the immutable in-memory execution snapshot and are not persisted in request/result artifacts or projected publicly.

Governance and prerequisite gates run before resolution. The immutable request CAS then precedes harness effects; retries reuse an exactly matching committed request, while changed image resolution, capture, policy, backend, or request identity conflicts before a second effect. Result admission requires one natural exit other than 137, independent bounded streams, exact request/plan/policy/snapshot/backend correlation, proven cleanup, and postflight equality of the qualified authority, immutable image resolution, engine NCPU, and every captured file digest. A result-CAS retry reuses the completed harness result and never reruns the workload.

## G11c–G11e Docker adapter, lifecycle, and qualification checkpoints

G11c replaces the unreleased multi-container planner and admission model directly. Its pure compiler emits exactly one verdict-container plan and, only for `docker-networked-v1`, one non-internal bridge plan. It derives collision-resistant names and ownership labels from host-sealed run, operation, request, plan, policy, qualification, and backend identities; uses the fixed user, workdir, namespace, capability, rootfs, resource, tmpfs, shm, bind, environment, and networking policy; and reserves destructive authority for durably recorded 64-hex full IDs.

Static, private-network-prestart, qualification-running-membership, and terminal decoders admit closed security semantics from bounded projections rather than exact Docker serialization. PID isolation admits Docker's empty/private equivalents; UTS admits only the safe Docker default empty form, and the compiler emits neither `--pid private` nor unsupported `--uts private`. The decoders accept harmless unknown fields, missing/null/empty optional values, unordered labels, ulimits, and tmpfs options, inherited non-conflicting image environment/labels, `aarch64`/`arm64` and `x86_64`/`amd64`, and seccomp `default`/`builtin`; they reject authority, identity, resource, privilege, namespace, mount, volume, port, device, lifecycle, or membership drift. Production admits an exact owned, non-internal bridge with zero endpoints before start and the exact container network configuration afterward; sole running membership is qualification-only, so fast exits do not create an observation race. Independent generated fixtures cover Linux rootful/rootless and Docker Desktop macOS arm64/amd64 shapes plus natural 125, 137, OOM/timeout, failed-start, optional-map, exact-absence, cidfile, and network-endpoint boundaries without importing production code.

Passive authority observation performs five bounded read-only context/version/info reads against a canonical regular executable (a CLI symlink is accepted only after resolving to such a target) and local Unix endpoint. It gates on genuine Docker Engine/Desktop, Linux server platform, cgroup namespace/default-or-builtin seccomp, and `MemoryLimit`, `SwapLimit`, `CpuCfsQuota`, and `PidsLimit`. Patch versions, cgroup strings, host-Python architecture, NCPU/MemTotal capacity, and optional security options are diagnostics rather than installed semantic equality facts.

G11d composes the `/2` lifecycle without adding authority publication. The descriptor-relative staging owner materializes only the immutable pre-CAS snapshot into an atomically published, read-only tree and revalidates exact membership, inode identity, modes, sizes, and hashes without following links. The bounded effects owner accepts only the compiled Docker vocabulary, canonical CLI/cwd, and closed environment. An fsynced journal persists the closed operation data, the daemon identity (endpoint, server OS, architecture), staging token, lifecycle, diagnostics, the reserved cidfile path, and exact full resource IDs. The host never precreates the cidfile: Docker creates it under child umask `077`. Startup always recovers unfinished journals before new mutation; a create without a recorded ID is resolved from the Docker-written cidfile or the exact-name, ownership-verified candidate set (G13 clarifications below). Cleanup uses only durably recorded full IDs, proves exact-ID absence from anchored recorded-ID error forms, removes staging without following links, re-observes authority, and removes the journal only after success. Ambiguity retains the private operation evidence and reports its operation ID and reason for operator diagnosis.

The production bridge composes the one-container harness behind exact `/2` passive authority. G11e adds a new five-probe qualification owner and two deliberately separate operations: qualification writes only an operator-selected private candidate, while installation revalidates that candidate against current semantic capability, implementation identity, policy, and profile before atomically publishing an exact `siffran.empirica.docker-spike-qualification-record/2` plus `siffran.empirica.docker-spike-qualification-pointer/2`. Ordinary runtime cannot qualify, repair, install, migrate, or acquire images; absent, legacy, malformed, or drifted authority freezes spikes unavailable. Live Docker acceptance remains deliberately unexecuted in automated development.

## Framework-owned runtime

One verdict container runs as `65534:65534` in `/work`, with `HOME=/work` and `TMPDIR=/tmp`; authored `HOME` and `TMPDIR` are refused. `/work` is a 512-MiB executable tmpfs, `/tmp` a 64-MiB noexec tmpfs, and `/dev/shm` is 64 MiB. Memory is 2 GiB with no additional swap; CPU is `min(2, engine NCPU)` sealed from a positive host capability; PIDs are 256; `nofile=1024`, `fsize=64 MiB`, `core=0`; stdout and stderr each have independent 1-MiB limits; production workload time is 120 seconds.

`docker-isolated-v1` uses network `none`. `docker-networked-v1` creates one private non-internal bridge for the verdict container, permits outbound egress, publishes no ports, and removes the bridge by its recorded full ID. Profile selection remains immutable host authority before run creation.

Natural exit zero is PASS. Natural nonzero is FAIL except 137, which is always unavailable; OOM, timeout, forced termination, output overflow, malformed required output, capture/authority drift, or cleanup ambiguity are also unavailable. Only supervised attach plus terminal state establishes natural exit.

## Semantic admission and lifecycle

Admission verifies the security-relevant semantic subset: exact recorded ownership and sealed image reference, bounded realization digest, executable/arguments, fixed workdir/user/environment, privilege and namespace isolation, no devices/ports/host mounts/volumes, read-only root, exact resources and approved mounts, and selected network mode. Missing/null/default forms and unordered sets/maps are normalized only where semantically equivalent; unrelated fields are ignored.

The minimal lifecycle is image resolution plus input capture, request CAS, staging, create and durable full-ID recording, one static inspect, supervised start/attach, one terminal inspect, force removal with volumes, exact-ID absence proof, optional bounded run-label diagnostics, network removal/absence when applicable, input/authority re-observation, and result CAS. Only recorded full IDs grant destructive authority. A global Docker inventory comparison is not required.

## G13–G14 requirement clarifications

These clarify the decision source without changing any frozen axis.

- **Guest argv is free.** The Docker effects layer admits only the closed `(argv[0], argv[1])` subcommand vocabulary; it never scans later tokens. docker/cli `create.go` stops flag parsing at the image (`SetInterspersed(false)`) and the planner proves every pre-image flag, so `cargo build`, `npm run build`, `pytest -k load`, `ps --pid 1`, or a guest argv mentioning `docker system prune` is author data, never Docker authority. An effect refused before any process launch records the create intent absent.
- **`Config.ExposedPorts` is metadata.** It is image `EXPOSE` metadata merged by Docker and publishes nothing, so it is neither inspected nor refused. Publication is `HostConfig.PortBindings`/`PublishAllPorts`, which stay refused with every other host-surface field.
- **Ownership is separate from policy.** A candidate container is adopted and recorded after an ownership-only check (exact `Id`, compiled `Name`, every Empirica label). Security static admission then runs on the same single inspection; its refusal is a clean unavailable followed by exact-ID removal, never a retained wedge. An empty, missing, or malformed cidfile is never absence: whatever the CLI exit, the journal is retained and the next recovery's exact-name candidate set decides. Exact absence is a nonzero exit, stdout empty or the `[]` docker/cli flushes, and an anchored stderr naming the recorded ID.
- **Recovery is version-stable.** A journal persists the closed operation data plus the identity of the daemon it ran on (endpoint, server OS, architecture). Recovery reads that data (names, labels, staging token, recorded IDs) without re-planning, so an unfinished journal stays recoverable after a plugin, planner, or implementation change. It runs only when that daemon identity equals the current one, so a capability or engine-version change never strands it; a journal from another endpoint or platform fails closed with its operation ID.
- **One visible limitation set.** Public-contract clause `evidence/spike/limits` is the single agent-visible list of what the agent chooses, what the host fixes, what is never available, the verdict rule, and the closed refusal reasons with a hint each. `make empirica-docker-support-contract-check` fails when it drifts from the code constants.
- **The spike Fault carries a closed `reason`.** An unavailable spike Fault carries one hyphenated `reason` from `GenericPreparationReason` or `GenericUnavailableReason` (both enumerated in `response.schema.json`) whenever the cause is attributable; it is a closed enum and never free text, paths, IDs, or private detail. Execution exceptions carry their reason by type. A Fault without a reason is an internal host failure.

## Qualification and capability authority

Supported MVP hosts are local-Unix-socket Linux containers on native Linux Docker Engine (rootful or qualified rootless) and Docker Desktop on macOS arm64/amd64. Qualification is capability-based: Docker identity, Linux server and server-native image platform, cgroup namespace/default-or-builtin seccomp, memory/swap/CPU/PID enforcement, immutable-ID creation, isolation/resource realization, bounded attach/termination, exact-ID cleanup, and selected network behavior. Patch versions, host-Python architecture, NCPU/MemTotal, optional security options, and cgroup diagnostic strings are not installed semantic equality gates.

An operator supplies one already-local Linux/server-native image with no declared volume and POSIX `/bin/sh`, `id`, `head`, `sleep`, `cat`, `touch`, `chmod`, `printf`, `command`, `test`, and `wget`, executable as uid 65534. Five mandatory fast probes cover sandbox realization PASS, natural 125 FAIL, output overflow unavailable, qualification-only five-second timeout unavailable, and profile networking; the networked probe's `wget` failure exits 46 and maps to `network-egress-unavailable`. OOM qualification is optional although runtime OOM/137 remains unavailable. Qualification proves only its recorded resources absent and journal/staging empty.

Runtime never pulls, builds, loads, logs in, starts/stops Docker, switches context, changes permissions, or inventories aliases for the author. Per-run passive verification checks the canonical executable path, version/info, endpoint/platform/capability facts, and implementation identity; it does not hash CLI/Python bytes or demand cosmetic serialized equality.

## Privacy and residuals

Request/result CAS, run-bound authority, producer attribution, names-only public environment projection, and exclusion of raw output, captured contents, host/staging paths, endpoints/configuration, credentials, and destructive IDs remain mandatory. Environment values persist in content-addressed private artifacts, and public plan identity can confirm guessed low-entropy values, so authored values must never contain secrets.

Multi-container services/topology, cross-architecture execution, image catalogs, image-declared volumes, authored users/workdirs/resources, global censuses, exhaustive inspect closure, mandatory OOM qualification, remote engines, Windows containers, Podman, SELinux relabeling, GPUs/devices, host mounts/ports, and runtime image acquisition are explicitly deferred.

Broad support requires the Tier-1 matrix and acceptance gates in the decision source; one local probe bundle or unit suite cannot establish it.
